# 工具编排、输出管理与可编辑性

读取时机：准备工程、工具选择、依赖缺失、交付与安装。G01–G14、C01–C07、P01–P07。

## 编排，不把所有工具装一遍

| 能力 | 首选 | 调用条件/边界 |
|---|---|---|
| 本地中文转录 | media-transcript-extractor / whisper.cpp | 从当前主片；已有已验收稿不重跑；须读当前 Skill，不写死私有机器路径 |
| 粗剪/账本 | chengfeng-cut | 仅源片尚未初剪且用户要求剪辑；本流程已初剪则跳过 |
| 字幕映射 | chengfeng-subtitle / 原 SRT 渲染 | 可复用时间映射思想，不能悄改冻结稿；已有烧录字幕不加第二层 |
| 语义分镜/门禁参考 | package-talking-head-video（娜娜开源 Skill） | 借鉴语义结构、证据与分阶段审核；**不能直接执行它的横屏坐标与二元模式规则** |
| HTML 动画/项目/预览 | HyperFrames 域 Skills | 当采用 HF 时先读 `hyperframes`；composition 读 core，动效读 animation/keyframes，CLI读cli，音频读audio，素材读media-use |
| 本地合成/精确按帧渲染 | Remotion | 本片 V5.2/V5.3 已实际使用；保留源码/props/lockfile，按当前官方文档及项目API实现 |
| 真实素材裁切/抽帧/封装/音频QA | FFmpeg / ffprobe | 已安装本地能力；音频修订不重渲染画面 |
| 额外媒体编辑/生成 | video-use / media-use / chengfeng-visual/export | 任务确有需要且实际可用时才读其当前 Skill；不是必须所有工具都跑一遍 |
| 剪映可编辑草稿 | ChatCut或其他适配器（候选） | 先核对准确仓库、版本、系统支持和导出格式；不能仅凭名称声称能导剪映工程 |

- **G01 发现能力**：检查已装 Skill、执行文件、模型、Node/浏览器、项目依赖及当前命令帮助。不把模型缓存、仓库目录或 Skill 安装当作工具已经运行成功。
- **G02 选择一条渲染主线**：默认延续当前项目已验收引擎；新项目有HF且用户偏好HF则检查其使用状态，不可用采用本地Remotion/FFmpeg。两者共享源锁和分镜，不为“全套调用”来回切引擎。
- **G03 HF 用量真实读取**：实际使用前运行当前支持的usage/doctor等；无法读取写“未知”，不猜恢复时间。网络/VPN/CLI故障先最小诊断，不改用户VPN/证书/认证/代理配置；更新先备份版本并验证，失败回退，报告实际版本。
- **G04 本地不自动降质量**：输出分辨率、fps、字体、素材、动画逻辑、码率/编码一致时，本地渲染不是低质量代名词；不同引擎也不能保证像素一致，需同帧比对和动态QA，禁止用静图轮播替代原动效。
- **G05 上游冲突覆盖**：娜娜仓库横屏左右轨、中央35%–65%留空、仅opaque/presenter-safe、8帧、1.6–3.2秒建议不能覆盖本用户9:16上下布局、允许中性半透明阅读层、圆形人物、18帧左右、3–5秒语义节拍。
- **G06 正确执行接口**：上游若有刚性规则冲突，用其组件/设计思想作为素材参考，修改本项目合成并标为9:16适配；不能一边原样执行上游Skill一边宣称完整符合上游与本用户两套互斥规则。
- **G07 框架≠审美**：粗糙通常来自锚点、素材、版式、动效执行不足，不能归咎只装了HF；装Remotion/ChatCut不自动让画面丰富。需逐项证据。
- **G08 安装权限**：用户让出方案时不先安装；用户明确需要安装再审准确源、许可证、依赖和脚本，遵循当前宿主权限。不要自动更新所有Skill覆盖用户改动。
- **G09 可续接**：所有Gate及用户批准保存当前版本/hash和范围；恢复未完成任务只做下一项，不重问已确定风格，不从头扫全部素材。
- **G10 骨架与资产分离**：时间轴、镜头模式、事件和进出场组成 motion skeleton；截图、录屏、图标、字体和音效是 assets。先验证骨架节奏，再替换资产，避免因换一张图重做全片逻辑。
- **G11 引擎能力差异测试**：HyperFrames、Remotion、FFmpeg/HTML覆层或ChatCut候选需要用同一短段分别验证帧精度、透明层、字体、可编辑性和导出质量；不能把“能运行”当作等效，也不为了比较安装全部工具。
- **G12 共享分镜合同**：无论主渲染引擎是哪一个，都读取同一timeline-lock、storyboard、事件ID和素材账本。切换引擎只能改变实现层，不能悄改SRT、镜头意图和已批布局。
- **G13 小组件优先**：沉淀标题锚点、数字滚动、圆窗、上下分屏、证据聚焦、答案滚动、划线反差和声音事件等小组件；经 2026-10-16 短段复刻验收后，新增素材弹性卡、点阵色带视差背景、短词贴片、参考节奏映射和动态 QA 合同。组件须可单独测试、替换和关闭，不建一个把所有题材绑死的巨型模板。
- **G14 本地参考复刻**：用户只要验证对标动效时，复用当前项目的 Remotion/FFmpeg 做最小独立短段，不自动调用对标产品的付费云服务。先锁定原视频、SRT、真实素材和分析范围；缺任一必要文件就报告，不生成替身。详细参数与验收见 [11-local-motion-replication.md](11-local-motion-replication.md)。

## 项目文件与可编辑交付

建议首次确认后创建一套，而非每轮新根目录：

```text
制作日期_视频标题/
  00_源文件/         原始/初剪的副本或引用，不覆盖剪映导出
  01_文字稿/         raw、corrected、approved SRT、源锁、词锚点
  02_配图素材/       真实截图、录屏段、解释素材、音效、许可账本
  03_分镜方案/       brief、storyboard、props、源码、审批
  04_预览/           同一项目所有视频版本和分版本关键帧审核目录
  05_成片/           只在最终验收后存放发布候选
```

- **P01 统一预览**：V3/V4/V5.6等都在现有 `04_预览`，每轮一个需审MP4。关键帧可有版本子目录，不另开平行视频项目。旧版按用户指定保留，不擅自删除。
- **P02 留底关联**：Obsidian发布记录用日期＋标题，保存文字、规则、来源索引、轻量QA/工程归档与媒体链接。大型视频、node_modules、模型和缓存放媒体工作目录，不当知识资产重复塞入Vault。
- **P03 源码交付**：保留可修改的工程、props、相对素材引用、字体/许可、时间轴、版本锁、voice/sfx stems和运行记录，排除密钥、私人素材、缓存和node_modules。说明在哪改文字/位置/大小/进出场。
- **P04 可编辑边界**：MP4图层已经烧录，导入剪映不会自动还原独立字幕、贴图和动画。不要承诺交付剪映源工程却只给MP4或Remotion代码。
- **P05 剪映选择**：用户要后调可以交干净主片＋SRT＋独立贴图/静音辅助视频＋事件表；支持时提供透明覆层，但其内部文字仍是烧录。原生剪映可编辑稿必须另测试具体适配器和该剪映版本，成功后再声明。
- **P06 透明层技术**：需要时用支持alpha的格式（如ProRes4444），实际验证alpha和帧率/时长，不以普通H.264 MP4冒充透明；在目标编辑器试导。未要求就不额外渲染第二份全片。
- **P07 反馈定位**：用户可按“时间点/原话＋要调整的对象＋想要效果”反馈。Agent主动对照词锚点定位，不要求用户懂时间线代码；局部改前后保留对比，源锁不随每次反馈改变。

## 成本感知

- **C01 工具优先**：扫描、hash、字幕解析、抽帧、裁切、媒体统计和校验用现有脚本/本地工具；同一数据不重复交给模型处理。
- **C02 最小上下文**：先读本项目入口、批准方案和差异；只加载当前阶段参考文件。长JSON先工具侧提取摘要，证据有冲突才回源文件。
- **C03 主模型判断**：信息关系、事实边界、用户冲突要求、设计和最终质量由主模型处理。无授权不多Agent；允许委派也仅可逆、明确、低风险工作，不能自动换provider或降低隐私边界。
- **C04 复用工程**：局部修改在源码/参数层改，不在已经烧录的MP4上补一层，又重新设计全部关键帧。
- **C05 首次审批后分段验证**：试新的动作/素材先局部关键帧/代表性动态测试，再全片。稳定的未变区域沿用验收，输出还需检查整体衔接。
- **C06 算清渲染成本**：只输出一个审核视频，避免1080版/同名副本/另一根目录重复生成。音频微调用码流复制。不把文件大小或Agent数量冒充Token节省证据。
- **C07 优先级**：安全、用户需求、正确性/验收高于省Token；该看的真实答案录屏和长SRT不能为了省Token跳过。
