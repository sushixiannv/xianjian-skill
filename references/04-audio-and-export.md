# V5.6 音效基线与真实成片验证

读取时机：音效方案、混音、仅音频修改、正式渲染/输出。A01–A26、Q01–Q10。

## 音频默认

- **A01 无背景音乐**：用户最终选择保留音效、完全去除背景音乐。不得把原先试过的 BGM、音效增强版音乐、V5.7 或 V5.8 当作默认。需要音乐时另提方案确认。
- **A02 无额外旁白**：“配音丰富度”在此案例指音效，而非 AI 代替用户口播。主片人声连续；人物圆窗、截图录屏、辅助演示视频静音。
- **A03 V5.6 音型**：短 whoosh 用于明显主图运动/转场，pop 用于关键标签/小图标落位，click-soft 用于轻节点/刻度，ping 用于关键状态，chime 用于少量收束。这是稳妥基线，不强制新片复制51个声音或同样的声音次数。
- **A04 克制的选声**：声音对应视觉动作/意义，不每个字幕刷新都响、不多声叠一击。全片同音型可建立关联，但不得凭“丰富”随机换硬币、警报、游戏疑问或突兀系统报错。用户曾提出语义声作为建议，试验未获通过，不能纳入强制规则。
- **A05 开头状态**：当前采用 V5.6 原开头，未采用后续重音替换。用户想要更抓耳且不似噪音的开头仍是独立待测课题；不得把这一需求描述成已在 V5.6 解决。
- **A06 时间基准**：同一个视觉 eventId 决定音效落点。裁前导静音、短尾淡出；不移动人声/字幕来适应长音效。采用帧量化的首次显现或主要落位时要在方案中明确，用户确认后固定。
- **A07 留白**：长答案滚动、关键结论阅读、连续解释中可少响/不响。不是每个3–5秒视觉变化都必须再播放一个声音。
- **A08 强度参考**：V5.6 音效单次样本峰值档：转场−7、主提示−9、细节−13、数字刻度−16、结尾−11 dBFS，总音效峰值−7。新视频先作为校准参考，不盲套总轨增益；不同素材相同峰值听感不同。
- **A09 单位明确**：dBFS/dBTP/LUFS 不是手机真实声压 dB SPL。含静音整轨 RMS 不是单次提示响度。测量记录与主观试听都要做，不能以数字正常掩盖“用户听不到/刺耳”。
- **A10 人声优先而非音效听不见**：V5.6 人声样本峰值约−4.40、RMS−19.73 dBFS；已编码全片−16.81 LUFS、−1.77 dBTP。这是一个验收实例，不是所有源片统一改成这些数值。人声一旦验收，不再加压缩/EQ/全轨增益；只调音效。
- **A11 分轨混音**：保存 voice/sfx/mix 和事件表，不从混好 AAC 中减音乐或“分离”出基线。无音乐版直接用独立人声＋音效相加，检查重采样/编码延迟。
- **A12 余量**：原始 PCM 不削波；编码后真峰值默认≤−1.5 dBTP。超限先缩减问题音效或控制局部能量，不悄悄压低已认可人声。是否使用限幅须记录，不能声称无处理却用了 limiter。
- **A13 素材许可**：可用 `media-use` 的已安装音效检索/离线资产和 `hyperframes-audio` 的混音规则；检查源许可并记录。不能因 Skill 代码开源推断素材可商用，也不能声称调用了音效生成模型却只做了本地检索。
- **A14 音频验收**：普通扬声器/手机尺度、耳机和单声道检查：可听见、不抢口播、尾音不黏下一句、重复不疲劳、无爆音/相位抵消。模型无法实际试听时明确主观待用户核验，不宣称听感通过。

## 声音分层与事件设计

- **A15 五层分开**：原口播、局部修复人声、音效、背景音乐、额外旁白分别管理。默认只有原口播＋克制音效；任何一层的存在都要在方案和分轨里显式记录。
- **A16 原人声是真源**：不为了“更专业”自动重配、变声、克隆或改语速。降噪、去爆音、修复只对问题片段小样测试，不能改变音色、节奏和已冻结同步；原始人声留底。
- **A17 旁白授权**：AI旁白/TTS/声音克隆只有用户明确要求时才进入方案，并核对声音来源、授权、隐私与用途；必须独立分轨和可关闭，不能冒充用户本人。
- **A18 背景音乐授权**：本用户当前默认关闭BGM。新片若要音乐，先提交曲风、许可、区间和对白下压方案；用户确认后才启用，且必须提供无音乐可回退版本或独立音乐轨。
- **A19 声音事件表先行**：渲染/混音前按 `audioEventId→visualEventId→语义→音型→强度→时长→许可` 写事件表。没有视觉或叙事事件，不为填满时间加声音。
- **A20 动作音型映射**：页面/镜头移动可用短whoosh，元素落位用pop/click-soft，数字完成或状态确认用轻ping，划线/描边用短刷写声，结尾收束可用chime；这些是候选家族，需局部试听，不能机械套每次动作。
- **A21 开头听觉钩子**：标题落位可测试一个比正文更有存在感、短而干净的声音，落点绑定标题主事件；不能用持续噪音、爆裂、突兀警报或未经试听的重低音。V5.6原开头仍是当前回退基线。
- **A22 克制重复**：同一音型建立一致性，但连续重复会疲劳；一段只保留最重要的1个听觉焦点，利用留白和强弱变化，不用“每个字幕按键声＋每个转场同一呼声”。
- **A23 语义声谨慎**：金币、错误、疑问、游戏提示等具象音色只有画面和语义都明确且局部测试通过才可使用。V5.7式突兀换音已被否决，不得因“丰富”自动恢复。
- **A24 视觉变化不等于必响**：3–5秒视觉变化是画面节拍，不是音效密度。证据阅读、长答案和连续思考段可以完全无音效，让人声承担注意力。
- **A25 混音目标**：同时看峰值、真峰值、整体响度与口播可懂度；音效必须在手机上可辨但不盖辅音。局部问题只改对应事件增益/包络，不能用全轨放大掩盖选声错误。
- **A26 同一事件ID**：画面进场、音效和必要震动/强调共享同一个事件ID与量化帧；修改视觉时自动暴露声音需要复核，避免出现声先到或画面先到。

## 渲染前到导出的检查

- **Q01 源锁一致**：主片/SRT/锚点、审批过的 storyboard/props/composition 版本关联；导出前再核对哈希。口播不变时不重新转录。
- **Q02 可解码代理**：HEVC 等浏览器不支持时生成相同时长、不重剪的 H.264/AAC 代理；验证时间对应和首尾，不把代理时长偏差当原片节奏改变。
- **Q03 工程确定性**：实际运行适用的编译/类型/素材加载检查；检查中文字体 fallback 和缺图。没有跑的 npm test/audit 等不能登记通过，不为了凑检测重新安装所有依赖。
- **Q04 同稿同图**：导出的视频在同时间点重新抽取审核帧，比对批准帧（允许编码误差），再人工看手机尺寸。不能“关键帧好看、成片实际太小”却只报告 build 成功。
- **Q05 全文件验证**：ffprobe 核对尺寸、帧率、时长、编码、音轨；FFmpeg 完整解码，检查黑段、尾黑、闪图和无声；检查每个过渡，不只首帧。
- **Q06 原音对齐**：不加音效时可直接复制原 AAC 轨重封装；加音效后检查人声分轨哈希和解码波形/相关性。抽检首、中、尾与案例关键点，采样率一致，记录偏移而不是仅比片长。
- **Q07 编码延迟陷阱**：本片早期渲染曾引入约42.625ms额外音轨偏移，最终改原片音轨重封装修复。这个数值只是历史案例，不能给每条视频盲目反向移动42ms。按实际检测修复。
- **Q08 技术≠同步创意**：音轨偏移0不证明图标正好卡到词；SRT不变也不证明所有重点没提前。对照事件表逐项回听尤其步骤、数字、案例、结论。关键帧只能证明布局，不证明运动自然。
- **Q09 音频修订不重渲染**：声音问题用独立分轨重混＋`-c:v copy`，校验视频码流与PTS/DTS一致、原人声不变；再验AAC真峰值。不为换几个音效重做全片画面。
- **Q10 真实交付**：只把实际渲染文件叫样片/成片；HTML、组件集、模拟截图不等于MP4。失败就报告失败，保留可恢复工程。技术通过/用户视觉通过/用户听感通过/发布批准四种状态分开记录。

## 最小音效事件账本

每项包含 audioEventId、visualEventId、cueId、关键词锚点、视觉帧、语义/动作、sound source、前导/尾部处理、duration、gain 或 peak target、许可、是否启用。用局部样例再全片检查，调音后标音频版本而非假装画面也换了版本。

正式交付保留：音轨处理前后测量、输出hash、冻结SRT hash、完整解码结果、实片关键帧、黑段检查、音轨偏移、音效落点、主观待验收事项。指标测量是证据，不用来代替观众判断。
